# 章节制作

先 `video_studio_context full:true` 读取作品、当前分镜修订、已采用素材与能力。制作继续使用当前 DSH 会话，插件只执行确定的媒体任务。

## 资产与通道

用户提供本地角色/场景参考图时，用 `video_studio_asset` 复制入当前作品媒体库；返回 assetId 后关联 `canon.entry.assetId` 或 `shot.assetIds`。引用真实图片参数，不能只把文件名或网址写进提示词就宣称已使用参考图。

图像生成候选可以通过 `video_studio_take kind:image` 采用，再使用其对应资产 ID 作为后续视频参考。一次先做明确的少量镜头验证视觉效果，之后按用户决定扩大范围。

先读取 diagnostics 中 providers/kinds/configured。生产通道在 DSH「设置 → 插件 → 视频工作室」配置 API Key、地址、图片/视频模型及配音模型/音色，保存后供后续请求使用；也可在设置中显式选择宿主环境变量。不要请求用户在聊天中粘贴凭证，不读取旧项目凭证。缺通道时指向该设置入口并保留可继续编辑的剧本与分镜。设置保存不代表供应商账户已经验证；旧任务配置不匹配时恢复原配置，不要切换账号自动重提。

## 预演与真实制作

- `mode:preview` 生成带“本地预演”标记的占位分镜片，只用于验证时长和剪辑。它不是模型生成画面，交付时必须说明。
- `mode:production` 调用配置好的真实服务，可能收费。沿用用户已经表达的制作范围，不重复询问同一授权，也不悄悄替换供应商扩大费用。
- 配音可以生成 audio 候选；本地配音取决于系统能力。无法配音时不要把静音结果描述为带声成片。

## 提交与查询

1. 确认分镜已通过结构检查，用户已决定制作本次指定范围，使用 decision approve 记录当前修订。
2. `video_studio_generate` 传 `chapterId`、明确 `shotIds`、kind、mode、providerId 和 operationId。
3. 同一次操作重复投递沿用 operationId；用户明确要求再生成一版时换新的 operationId。输入变化不能借同一 operationId 静默覆盖旧任务。
4. 提交立即返回持久任务。用 `video_studio_job action:list` 查询；恢复已有任务用 action:resume，查询不等于再次 generate。
5. unknown 表示供应商是否接受不确定。不要盲目重新提交，先核对远端任务或让用户决定如何处理。
6. 用户停止用 action:cancel。远端可能继续运行，应报告真实状态；停止后返回的候选不能自动采用或触发后续制作。

## 采用与局部重做

成功表示素材已落盘并可解码。把候选回给用户比较，用户选择后调用 `video_studio_take`。每个镜头可采用 image/video/audio 三种媒介各一个版本，旧候选继续保留。

只修改某镜就修订该镜，再重新检查和批准。已生成素材引用精确输入，旧结果不会冒充新修订的产物。其他镜头未变时可继续使用，不因全章修订号变化而重做整章。

## 合成本章

每镜至少采用视频或图片候选。已采用图像可以作为静帧视频，必须说明其表现形式。按照实际配音检查镜头时长；声音过长要调整时长或重新安排内容，不静默截掉台词。

`video_studio_render` 传 chapterId，subtitles 默认 true。voice=true 表示缺少已采用音频时使用本地试配音；先检查本机能力。voice=false 只关闭这个补配功能，已经采用的音频仍会参与合成。

渲染只使用已有素材和本地合成，不调用图像/视频服务。查询 job list 获取 renders 和 files；files 中的本地绝对路径用于在当前 DSH 会话交付图片、声音、MP4、SRT 与时间线。只有 available=true 的文件才作为可用产物返回；说明候选所属镜头和是否已采用。使用宿主已有的文件或媒体呈现能力，不创建插件前端、播放器或独立 HTTP 下载服务。检查实际时长、必要音轨和文件可解码性，再向用户汇报。预演/静帧与真实生成片段如实区分。

剪映草稿、口型同步、自由画布和精细时间线编辑不在当前实现内，不得声称支持。成片后用 canon/fact/decision 保存需要延续的角色设定、章末状态和用户偏好，下一章从 context 开始。
